## 4. Levers (the affordance map)

**Context: the per-request 32k window, not the KV pool, is the binding limit.**
- In public local runs, all 75 of 75 context overflows ended with an empty patch.
- Our single agent runs 80 turns into one window. Malformed-call drift and submit loops appear late in sessions, which is context degradation.
- Levers:
  - staged agents with fresh contexts;
  - state handover of short reports;
  - capping tool output;
  - narrow tool requests;
  - append-only history (prefix-cache friendly; ADK only appends).

**Tools: the shape of a call decides whether it can be malformed.**
- run_skill_script has two string arguments, and the model swallows one in 54–84% of calls late in sessions.
- run_command has one string argument: **0 malformed** (000360).
- Skill scripts are ours, so their output format, caps and hints are all levers.

**Throughput: vLLM batches concurrent requests, and Gemma 4's KV is small per context.**
- Parallel branches are cheap, unlike ARC, where KV and mamba slots crashed f30h.
- Levers:
  - ParallelAgent locators;
  - parallel review;
  - parallel attempts. Parallel *edits* collide in one workspace, so attempts must propose patches as text and one stage applies them.

**Budget/sampling (measured publicly):**
- thinking 4,096 (2,048–6,144 is flat; off is much worse); we ran an unmeasured 1,024;
- an 8-min clock (half of eventual fixes appear after 4 min) against our 6;
- the call cap matters mostly for the wall.

**ARC (Zatravkin/Poluektov) lessons that transfer:**
- request shape and context management;
- prefix-cache-friendly append-only history;
- concurrency as throughput;
- output size as context.

What doesn't transfer is server tuning: memory fraction, hicache and mamba slots are fixed by the organisers.
